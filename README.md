#### 一、联机服务端（自研 C# 后端）

基于 .NET Core 从零自研，未使用第三方商业框架。

| 模块 | 技术细节 |
|:---|:---|
| Socket 通信层 | 基于 `SocketAsyncEventArgs` 实现高并发 TCP 长连接管理，封装心跳保活、超时断开、消息粘包拆包（4 字节包头定长 + Protobuf 变长包体） |
| 协议层 | 全量消息体用 **Protobuf** 定义，客户端与服务器共用同一套 `.proto` 文件。消息 ID 路由使用特性标注 + 启动时反射扫描注册，`[MessageHandler(10001)]` 自动映射处理函数 |
| 帧同步（Lockstep） | 战斗逻辑跑 **帧同步**：客户端操作上报 Server → Server 汇总为帧命令（`FrameCommand`）→ 广播给所有玩家 → 客户端各自按帧执行。随机数种子由 Server 在开场统一下发，保证所有客户端随机结果确定性一致 |
| Buffer 帧抗延迟 | 客户端缓冲 3 帧后开始执行，用 Buffer 吸收网络抖动。当客户端落后时触发**追帧模式**（提高逻辑帧率快速追赶），帧数据超出缓冲区上限时丢弃旧帧（Server 侧保留历史帧用于重连） |
| 定点数（Fix64） | 因 `float` 在不同 CPU / 平台存在精度差异，帧同步中涉及随机逻辑的计算全部使用 **定点数 Fix64** 替代浮点，确保确定性 |
| 断线重连 | Server 保留玩家 `Session` + 断线期间全部帧命令。客户端重连握手成功后，Server 批量下发断线帧数据包，客户端逐帧**快进执行**追至当前帧后恢复正常逻辑 |
| 房间系统 | 实现匹配队列 → 创建/加入房间 → 房间内玩家状态机（`等待中 → 已准备 → 战斗中 → 结算`）。**关键约束检查**贯穿全程：加入时校验卡组合法性、战斗中校验出牌合法性（费用/回合状态），防止客户端篡改 |
| 服务端分层架构 | **网关层**（连接管理、心跳、协议路由）→ **逻辑层**（房间匹配、卡组校验、排行榜）→ **战斗层**（帧同步引擎，独立进程部署，崩溃不影响大厅和匹配）。三层之间通过内部 TCP 协议通信 |
| 数据持久化 | 玩家数据（卡组、等级、道具、战斗记录）存入 **MongoDB**，利用其 Document 模型直接序列化 C# 对象，避免 ORM 映射开销。热数据（房间状态、战斗中途数据）使用 **Redis** 缓存，战斗结束后持久化到 MongoDB 并清理缓存 |
| 服务端热更新 | 网关层常驻不下线，逻辑层和战斗层支持**程序集热加载**：替换 DLL 后新战斗使用新版逻辑，旧战斗保持旧版跑至结束 |

#### 二、客户端架构

- 基于 **QFramework.cs 四层架构** 搭建项目骨架，严格遵循 CQRS 模式：`Controller → Command → Model → Event → View`，数据变更通过 `BindableProperty` 自动驱动 UI 刷新。
- 接入 **HybridCLR** 实现纯 C# 热更新，主包仅含引擎与框架，业务 DLL 全部热更。资源管理用 **YooAsset** 分包（主包/战斗/卡牌美术/音效），**Luban** 管理配置表管线。
- 战斗系统：效果采用**组合模式**（`ManualTargetEffect[]` + `OtherEffects[]`），钩子系统（虚弱/易伤/力量）统一注册分发消除 if-else 膨胀，**UniTask** 编排出牌时序。

#### 三、CI/CD 自动出包 & 飞书交付

- 使用 **Jenkins** + **PowerShell** 搭建全自动出包管线。代码提交 → Jenkins 自动拉取 → 切平台 → `BuildPipeline.BuildPlayer` → YooAsset 打 AB 包 → 压缩归档至内网 **Nginx 文件服务器**。
- 构建完成后通过 **飞书机器人 Webhook** 自动推送通知：版本号、平台、包体大小、下载链接、构建耗时、Git 提交记录摘要。构建失败自动 @相关人员并附加错误日志。
- 支持**参数化构建**（Development Build / Clean Build / IL2CPP 等勾选项），策划和测试无需安装 Unity 即可自助取包。
